# 云端 Claude 操作 Mac 项目

Claude CLI、订阅登录和模型请求在 VPS；项目源码、依赖、构建和测试在 Mac。挂载、Bash 路由和 `#vps` 的机制由启动器的追加提示说明，这里只列使用约定。

- 不创建 VPS 项目副本，不在 VPS 安装项目依赖或执行项目构建、测试。挂载内的 git、Glob/Grep 已自动在 Mac 执行。
- `#vps` 只认命令首行或末行末尾。mac-project 调用和 `~/.claude` 下的技能脚本自动留在 VPS；与项目工具链写在同一条命令会被拒绝，拆成两条。scratchpad 等 VPS 路径在 Mac 不可见。
- 浏览、搜索和对照代码优先合并为一条 Mac Bash（`rg`、`sed -n`）；只对要修改的文件用 Read。Edit 经 SSHFS 往返数秒，同一文件的多处修改合并为一次。
- 计划、任务、技能和子 agent 保留原生机制；子 agent 的 Bash 同样经 hook 在 Mac 执行，派发时说明当前目录是 Mac 项目挂载。
- 首次接手核对实际项目规范与 Git 状态。修改后在 Mac 跑项目要求的相关测试并读回 diff。
- Mac 离线时停止依赖步骤，不在 VPS 执行项目测试。断连后的文件修改可能已发生，先读回核对再决定是否重试。
- hooks、MCP、语言服务器和插件不会因 SSHFS 自动迁移到 Mac，启用前核对实际执行主机。
- 使用 Mac 登录账号的正常权限，挂载和提示词不是目录隔离。只处理用户选择的项目，不读取无关个人文件或凭据，不使用 sudo。
- 运行环境遵循项目规范及已有管理器；不因 shell PATH 指向旧全局运行时就直接采用。
- 工具审批模式与模型安全规则独立；不要把跳过审批当作额外系统权限。
